Send the same request twice, at the same moment.

doubledip sits between your app and Postgres, holds two copies of a request right before they write, and shows what your database looks like afterwards. Double-redeemed coupons, negative balances and duplicate accounts, reproduced on demand.

Below are replays of real runs against the example shop: every statement, every timing, every row is what doubledip recorded.

How it works

Record. The request runs once through doubledip's Postgres proxy. Every statement, its transaction and isolation level are noted.
Find. The real Postgres parser spots reads followed by writes to the same table: the window a second request can slip into.
Serial runs. The two requests run one after the other, in both orders, from the same data. Those are the correct outcomes.
Race. Both start together. The proxy holds the first to reach the write until the second gets there, then releases both.
Compare. Any row no serial order produces is a confirmed race, shown with the fix.
